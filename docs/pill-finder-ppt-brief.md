# 알약 찾기 도우미 — 과제 제출 PPT 제작 요청서 (Claude Design 전달용)

## 0. 반드시 지켜야 할 것 (필수 목차)

> **아래 목차는 과제 제출 요건이다. PPT에 빠짐없이, 이 순서대로 반드시 넣어야 한다.**
> 다른 슬라이드는 더하거나 빼도 되지만, 이 세 슬라이드와 각 항목은 생략·통합·이름 변경 없이 그대로 들어가야 한다.

**과제 제출 PPT 목차 (필수)**
1. **표지**: 프로젝트 이름, 이름·학번, 제출일
2. **SOW (작업 범위)**
   - 목적: 무엇을 해결하는지 한 줄로
   - 산출물: 화면 시안, 동작하는 기능, 시연 영상
3. **구성과 데이터 흐름 (6절)**: 서버, 모델, RAG, MCP가 어떻게 이어지는지 **도식 한 장**

- 필수 슬라이드 제목에는 위 이름(표지 / SOW (작업 범위) / 구성과 데이터 흐름)을 그대로 쓴다.
- `[ ]`로 표시한 값은 제출자가 채울 자리다. 내용을 지어내지 말고 자리 표시를 그대로 둔다.

## 1. 필수 슬라이드 내용

### 슬라이드 1 · 표지 (필수)
- 프로젝트 이름: **알약 찾기 도우미**
- 부제(선택): 알약 각인·색·모양이나 사진으로 무슨 약인지 후보를 찾고, 식약처 공식 자료로 답하는 웹 도구
- 이름·학번: `[이름]` · `[학번]`
- 제출일: `[제출일]`

### 슬라이드 2 · SOW (작업 범위) (필수)
**목적 (한 줄)**
> 집에 남은 알약이 무엇인지 각인·색·모양이나 사진으로 후보를 찾고, 식약처 공식 자료만 근거로 약 정보와 질문에 답한다.

**산출물** (세 가지 모두 표시)
| 산출물 | 내용 | 상태 |
|---|---|---|
| 화면 시안 | claude.ai/design 시안을 정적 웹페이지로 옮김. 화면 1 약 찾기 · 2 후보 비교 · 3 약 정보와 질문 | 완료 |
| 동작하는 기능 | 실제 식약처 자료로 후보 찾기·이름 검색, 공식 원문·쉬운 말 요약, 근거 기반 질문 답변, 사진으로 각인 읽기, 개인정보 가리기, 답변 검토 | 완료 (서버에서 동작) |
| 시연 영상 | `[시연 영상 링크 또는 QR — 제출자가 넣음]` | `[ ]` |

작게 덧붙일 범위 (선택)
- 하지 않는 것: 진단·복용 지시, 로그인, 결제, 처방전 사진, 병용 금기 확인
- 결과는 "후보"이며 복용 전 약사 확인을 안내함

### 슬라이드 3 · 구성과 데이터 흐름 (6절) (필수, 도식 한 장)
**한 장의 도식**으로 그린다. 상자(구성 요소)와 화살표(오가는 자료)를 아래 그대로 쓴다. 필수 항목인 **서버, 모델, RAG, MCP**가 도식에서 바로 눈에 띄도록 각각 라벨을 붙인다.

**상자**
| 구분 | 상자 이름 | 설명 |
|---|---|---|
| 사용자 | 브라우저(폰) | 화면 1·2·3 |
| **서버** | 앱 서버 (FastAPI, 포트 8000) | 후보 비교·이름 검색은 코드가 직접 함. 비용 스위치, 하루 한도 |
| 자료 | 공공데이터포털 (식약처) | 낱알식별 25,501건, e약은요 4,749건. 매주 월 03:00 자동 갱신(cron) → 서버 파일로 저장 |
| **모델** (수업 내부) | Local LLM — Qwen3 4B | 쉬운 말 요약, 답변 작성(무료 모드), 개인정보 가리기 |
| **RAG** (수업 내부) | BGE-M3 임베딩 + Chroma (`pill-docs`) | 질문한 약의 공식 문단에서 근거 최대 5개 |
| **모델** (외부, 스위치) | CLOVA HCX-005 | 사진으로 각인 읽기, 요약·답변 작성. 월 비용 상한 5,000원 |
| **모델** (외부, 스위치) | Claude Haiku 5.5 (API) | 답변 검토 (근거 밖 내용·단정적 복용 지시) |
| **MCP** | pill-finder MCP 서버 (stdio) | 앱과 같은 자료·같은 RAG를 MCP 도구 4개로 제공: `search_pills`(각인·색·모양 → 후보), `find_drug_by_name`, `get_official_info`(공식 원문), `find_evidence`(RAG 근거 문단). 모두 읽기 전용, 외부 유료 호출 없음 |
| MCP 클라이언트 | Claude Code | pill-finder MCP 서버를 등록해 대화 중에 약 찾기·근거 찾기 도구를 부름 |

**화살표 (번호 순서대로 그리면 질문 한 번의 흐름이 됨)**
1. 공공데이터포털 → 앱 서버: 자료 전체 (주 1회)
2. 브라우저 → 앱 서버: 각인·색·모양 → 후보 5개 (서버 코드가 비교, 외부 호출 없음)
3. 브라우저 → 앱 서버 → CLOVA: 사진 (사용자가 자른 부분만, 위치 정보 제거·축소) → 각인·색·모양 값
4. 브라우저 → 앱 서버 → Qwen: 질문 → 개인정보를 [가림]으로 바꾼 문장 → **사용자 확인 후에만** 다음 단계
5. 앱 서버 → RAG: 가린 질문 → 근거 문단
6. 앱 서버 → CLOVA 또는 Qwen: 가린 질문 + 근거 → 답변
7. 앱 서버: 코드 규칙 검사 (단정 표현, 근거 번호 없는 문장)
8. 앱 서버 → Claude: 가린 질문 + 근거 + 답변 → 검토 결과
9. 앱 서버 → 브라우저: 진행 단계를 실시간 표시(SSE) → 답변·근거·검사·검토 결과
10. Claude Code(MCP 클라이언트) ↔ pill-finder MCP 서버(stdio): 도구 호출 → 앱과 같은 자료 파일에서 후보·원문, 같은 RAG에서 근거 문단 (웹 화면을 거치지 않는 두 번째 입구)

**도식에 함께 표시할 경계**
- "수업 내부 서버"(Qwen, RAG)와 "외부 서비스"(CLOVA, Claude)를 다른 색 영역으로 나눈다.
- 외부로 나가는 것은 가린 질문, 자른 사진, 공개 원문뿐이고 질문·사진은 저장하지 않는다는 점을 짧게 적는다.
- 스위치 3개(`PHOTO_READ`, `CLOVA_TEXT`, `CLAUDE_REVIEW`)를 모두 끄면 외부 서비스 영역 없이 동작한다(무료 모드)는 것을 점선 등으로 표시한다.

**MCP 표시 방법**
- 앱 서버 옆에 "pill-finder MCP 서버"를 두고, 둘이 **같은 자료 파일과 같은 RAG(BGE-M3·Chroma)**를 함께 쓰는 모습으로 그린다(웹 화면과 MCP는 같은 기능의 두 입구).
- MCP 서버 위에 "MCP 클라이언트: Claude Code"를 두고 화살표에 "도구 4개 (stdio)"라고 적는다.
- MCP 도구는 읽기 전용이고 CLOVA·Claude 같은 외부 유료 서비스로 가는 화살표가 없다는 점이 보이게 한다.

## 2. 선택 슬라이드 (필수 목차 뒤에 넣어도 되는 내용)

필수 세 장 뒤에 아래를 필요한 만큼 넣는다. 순서와 개수는 자유.

**A. 화면 흐름** — 화면 1 약 찾기(직접 입력 / 사진 / 이름 검색) → 화면 2 후보 비교(최대 5개, 일치 항목 배지, 출처와 자료 기준 시점) → 화면 3 약 정보(요약 / 원문 / 질문하기). 처방약은 안내와 의약품안전나라 링크만.

**B. 각인 비교 규칙** — 대소문자·공백·하이픈 무시, 0/O·1/I/l·5/S·8/B 같은 글자로 봄, 앞뒤가 바뀌어도 찾음. 점수: 각인 완전 일치 40 > 부분 일치 20, 색 +15, 모양 +15, 캡슐 +10 → 상위 5개. 실제 자료에서 찾은 점: 각인 칸에 "분할선"·"마크" 글자가 섞여 있어 빼고 비교, 한 글자 각인("Q")은 부분 일치에서 제외.

**C. 안전장치** — 응급 표현이면 119 안내를 답변보다 먼저 · 외부로 보내기 전 개인정보 가리기 + 사용자 확인 · 근거 문단만으로 답하고 없으면 "공식 자료에 해당 내용이 없습니다" · 코드 규칙 검사 · Claude 검토 · 요약에 원문에 없는 숫자가 있으면 경고.

**D. 비용 스위치와 무료 모드** — 표: 스위치 / 켰을 때 / 껐을 때. CLOVA 월 상한 5,000원을 넘으면 그 달은 자동으로 무료 모드. 사진 읽기 한 장 약 2.3원, Claude 검토 1회 약 0.3원 수준. 개발 중 시험에 쓴 CLOVA 비용 20.22원.

**E. 검증 결과** — 표: 무료 모드 흐름 21개, 스위치 켬 흐름 18개, 자르기 상자 12개, 자가 검사 4개 파일 모두 통과. 속도: 요약 18~22초(저장 후 즉시), 질문 답변 2~5초(처음 약 6초), Claude 검토 2~3초.

**F. 한계와 다음 할 일** — 실제 폰 화면 확인, 약 10종 사진·연습 질문 20개로 정확도 측정, 서버 상시 실행, 식약처 자료 이용 허용 문의.

## 3. 디자인 지침

- 16:9, 한국어. 본문 글꼴 Pretendard (앱 화면과 같은 글꼴).
- 색은 앱 디자인 시스템과 맞춘다: 글자 `#111111`, 본문 `#374151`, 보조 글자 `#6b7280`, 배경 `#ffffff`, 카드 `#f5f5f5`, 강조 `#3b82f6`.
- 화면 캡처 자리는 `[화면 캡처: 화면 1 / 2 / 3]`처럼 비워 둔다(캡처는 제출자가 넣음).
- 한 슬라이드에 하나의 메시지. 숫자는 위 내용 그대로 쓰고 새로 만들지 않는다.
- 다시 한 번: **표지, SOW (작업 범위), 구성과 데이터 흐름(도식 한 장)** 세 슬라이드는 반드시 포함한다.
