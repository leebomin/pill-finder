# 알약 찾기 도우미 (가칭)

알약 사진이나 각인·색·모양, 약 이름으로 무슨 약인지 후보를 찾고, 공식 자료를 근거로 약 정보와 질문에 답해 주는 웹 도구.

## 1. 문제와 사용자
- 불편: 집에 남은 약이나 받은 알약이 무엇인지, 어떤 주의사항이 있는지 알기 어렵다.
- 기준 사용자: 혼자 사는 대학생·사회초년생. 누구나 쓸 수 있게 열어 둔다(로그인 없음).
- 이 도구는 진단이나 복용 지시를 하지 않는다. 결과는 "후보"이며 복용 전 약사 확인을 안내한다.

## 2. 범위
### 대표 흐름
(사진 → 이미지 모델이 각인·색·모양을 읽어 입력칸을 채움) 또는 사용자가 각인·색·모양을 직접 입력
→ 사용자가 확인·수정 → 코드가 공식 자료에서 후보 최대 5개 선택 → 사용자가 비교해 선택
→ 공식 정보·쉬운 말 요약 → 근거 기반 질문

### 핵심 기능
1. 낱알 후보 찾기: 사진(스위치) 또는 각인·색·모양 직접 입력, 약 이름 검색
2. 공식 정보 원문 + 쉬운 말 요약 (일반의약품만)
3. 근거 기반 질문 (RAG 근거 → 답변 작성 → 코드 규칙 검사 → Claude 검토(스위치), 일반의약품만)

### 비용 스위치 구조
모든 유료·외부 모델 단계는 서버 환경변수 스위치로 켜고 끈다(변수 이름은 예시).
| 스위치 | 켰을 때 | 껐을 때 (무료) |
|---|---|---|
| `PHOTO_READ` | 사진 → HCX-005가 각인·색·모양 값을 채움 | 사진 칸 숨김, 직접 입력·이름 검색만 |
| `CLOVA_TEXT` | 요약·답변을 CLOVA가 작성 | 요약·답변을 Local LLM(Qwen3 4B)이 작성 |
| `CLAUDE_REVIEW` | Claude가 답변 검토 | 코드 규칙 검사만, "검토하지 않은 답변" 표시 |
| `AUTO_REFRESH` | 주 1회 자료 자동 갱신 | 예약 실행이 바로 종료 |

- 현재 방침: HCX-005와 Claude를 쓸 수 있으므로 `PHOTO_READ`·`CLOVA_TEXT`·`CLAUDE_REVIEW`를 켜고 시작한다.
- 모두 끄면 공공 API 외에는 외부 호출이 없는 **무료 모드**로 대표 흐름 전체가 동작해야 한다.
- CLOVA 월 비용 상한(예: 5,000원, 수업 안내에 맞춰 조정)을 넘으면 앱이 해당 단계를 자동으로 무료 모드로 바꾼다.

### 약 범위
- 후보 찾기: 낱알 식별 자료 전체(일반·전문의약품)
- 정보·질문: e약은요에 있는 일반의약품만. 처방약은 안내와 의약품안전나라 링크만 표시

### 제외
로그인, 관리자 화면, 결제, 약 봉투·처방전 사진, 병용 금기 확인, 메신저 알림

### 사진 기능 판단 기준
첫 주 시험에서 HCX-005가 고치지 않은 상태로 각인을 정확히 읽은 약이 10개 중 6개 미만이면
사진은 "입력칸 채우기 보조"로만 두고, 직접 입력을 기본 화면으로 한다.

## 4. 기술 역할
| 단계 | 담당 | 왜 | 받는 것 → 만드는 것 | 연결 |
|---|---|---|---|---|
| 자료 받기 | 코드 | 정해진 조회 | 공공 API 응답 → 서버 파일 | 서버에서 HTTP |
| 검색 자료 만들기 | RAG (BGE-M3·Chroma) | 질문 근거 찾기 | e약은요 항목별 문단 → 새 컬렉션 pill-docs(company-docs와 분리) | 2026-11-11: 전체를 미리 색인하면 수 시간(456만 자, 초당 228토큰)이라 **질문이 들어온 약만 그때 색인**하고 수정일(`updateDe`)이 바뀌면 다시 색인. 검색은 그 약의 문단 안에서만 |
| 사진 읽기 (`PHOTO_READ`) | CLOVA HCX-005 | 수업 기술 중 사진을 읽는 유일한 모델 | EXIF 제거·축소한 사진 → 각인·색·모양 값(약 이름 추측 금지) | 기존 clova.py 재사용 |
| 후보 고르기·이름 검색 | 코드 | 조건 비교는 코드가 함 | 확인된 값 또는 이름 → 후보 최대 5개와 일치 항목 | 앱 내부 |
| 응급 표현 감지 (항상) | 코드 | 위급한 질문에는 답변보다 응급 안내가 먼저 | 질문 → "과다 복용", "삼켰" 등 표현이 있으면 응급 안내 표시 | 앱 내부 |
| 쉬운 말 요약 | CLOVA HCX-DASH-002 또는 HCX-007 (`CLOVA_TEXT` 켬) / Local LLM (끔) | 한국어 설명 작성 | 공식 원문 → 요약(약마다 1번 생성 후 저장) | 기존 clova.py / 기존 앱의 Ollama HTTP 연결 |
| 질문 가리기 (외부 전송 단계가 켜졌을 때만) | Local LLM (Qwen3 4B) | 질문 속 건강 정보가 밖으로 나가기 전에 수업 내부 서버(local-llm-chat)에서 처리 | 질문 → [가림] 처리된 질문 → 사용자 확인 | 기존 앱의 Ollama HTTP 연결 재사용 |
| 근거 찾기 | RAG (리랭커는 기본 끔) | 공식 문단만 근거로 사용 | 질문 → 근거 문단 최대 5개 | 앱이 순서를 정함 |
| 답변 작성 | CLOVA HCX-007 (`CLOVA_TEXT` 켬) / Local LLM (끔) | 한국어 답변 | 질문 + 근거 문단 → 답변(근거 없으면 답하지 않음) | 기존 clova.py / Ollama HTTP |
| 답변 규칙 검사 (항상) | 코드 | 모든 모드에서 남는 최소 안전장치 | 답변 → 단정 표현("드세요", "복용하세요" 등)과 근거 번호 없는 문장 표시 | 앱 내부 |
| 답변 검토 (`CLAUDE_REVIEW`) | Claude (`claude -p`) | 근거 밖 내용·단정적 복용 지시 검토 | 가린 질문 + 근거 + 답변 → 검토 결과 | `claude -p --tools "" --strict-mcp-config --model <가벼운 모델> --max-budget-usd <상한>`. 파일·셸·MCP 모두 끔. 옵션은 설치 버전에서 재확인 |
  - 2026-11-11 실제: `claude -p` 대신 서버 `.env`의 Anthropic API 키로 `claude-haiku-5-5`를 직접 부름(사용자 결정). 서버에 Claude 세션 기록이 남지 않음. 결과는 JSON 형식(ok, issues)으로 받고, 약 이름도 함께 보냄(빼면 "제품명이 근거에 없다"는 오탐). 1회 2~3초

- MCP (2026-11-11 추가): `/opt/pill-finder/pill_mcp.py`가 앱과 같은 자료·RAG를 MCP 도구 4개(후보 찾기, 이름 검색, 공식 원문, 근거 찾기)로 제공. stdio, 읽기 전용, 외부 유료 호출 없음. Claude Code에 local 범위로 등록
- 질문 가리기는 `CLOVA_TEXT` 또는 `CLAUDE_REVIEW`가 켜져 질문이 외부로 나갈 때만 실행한다. 둘 다 꺼져 있으면 질문은 서버 밖으로 나가지 않으므로 가리기와 확인 단계를 건너뛴다.
- 요약 모델은 첫 주에 HCX-DASH-002와 HCX-007을 비교해 정한다(가벼운 모델 우선).

### 각인 비교 규칙 (코드)
- 대소문자·공백·하이픈을 무시하고, 헷갈리는 문자(0/O, 1/I/l, 5/S, 8/B)는 같은 문자로 본다. 자료 각인 칸의 "마크"·"분할선" 글자(예: `V분할선T`)는 빼고 비교한다.
- 완전 일치 > 부분 일치 순으로 점수를 매기고, 색·모양 일치를 더해 상위 5개를 고른다. 앞/뒤가 바뀐 경우도 비교한다. (분할선은 입력칸이 없어 아직 점수에 넣지 않음)
- 부분 일치: 입력이 각인의 일부이면 인정. 각인이 입력 안에 들어 있는 경우는 각인이 두 글자 이상일 때만 인정(한 글자 각인 `Q`·`Z`가 아무 입력에나 걸리는 것을 막음).
- 각인을 입력하면 각인이 맞는(완전·부분) 약만 후보로 한다. 색·모양만 맞는 약은 수천 개라 후보에서 뺀다.
- 색: 자료의 색은 "노랑, 투명"처럼 여러 개일 수 있어 앞·뒤 색(`COLOR_CLASS1·2`) 중 하나라도 맞으면 일치. 모양: 원형·타원형·장방형 외 8종은 "기타"로 묶는다. 캡슐 여부: 제형 이름에 "캡슐"이 있는지.
- 각인이 한쪽에만 있으면 다른 칸은 비워 둔다. 빈 칸은 "모름"으로 보고 비교에서 뺀다(그쪽에 각인이 있는 약도 후보에 남음).
- 문자 대신 로고가 새겨진 약은 각인 칸에서 "각인 없음" 또는 "마크(로고) 있음"을 고르게 하고, 마크 항목(`MARK_CODE_*`)이나 각인 칸의 "마크" 표기로 거른다. "각인 없음"은 앞·뒤 각인과 마크가 모두 없는 약(159건).

### CLOVA 비용 관리
- 사용량 카운터: 응답의 사용량으로 하루·한 달 누적 금액을 계산한다(기존 clova.py의 금액 계산 재사용). 월 상한을 넘으면 그 달은 해당 단계를 무료 모드로 바꾸고 화면에 표시한다.
- 출력 길이 제한: 요약·답변에 최대 출력 토큰을 건다(출력 단가가 입력보다 높음).
- 사진 축소: 보내기 전에 서버에서 크기를 줄인다(이미지 토큰 계산 방식 확인 후 기준 결정).
- 리랭커는 기본으로 끄고, BGE-M3 검색 결과가 부족할 때만 켠다.
- 참고 단가(기존 앱 요금 파일, 2026-11-04, VAT 별도): HCX-005·리랭커 입력 1,000토큰당 1.25원, 출력 1,000토큰당 5원. HCX-007·HCX-DASH-002 단가는 확인 필요.

## 6. 화면
1. **약 찾기**: 각인 앞/뒤 입력칸("각인 없음"/"마크(로고) 있음" 선택 포함), 색·모양 선택 버튼, 약 이름 검색칸. `PHOTO_READ`가 켜져 있으면 앞·뒤 사진 올리기와 촬영 팁("알약만 보이게, 손·얼굴·처방 봉투가 나오지 않게")이 보인다. 올린 사진은 **미리보기와 자르기**로 확인한 뒤, 사용자가 "사진으로 각인 읽기"를 눌러야 전송된다(버튼 바로 아래 안내: "위치 정보를 지운 뒤 CLOVA로 보내 읽고, 사진은 저장하지 않습니다."). 사진에서 읽은 값은 입력칸에 채워진다.
   - 직접 입력은 각인·색·모양을 모두 정해야 "후보 찾기"로 넘어간다(각인은 "각인 없음"·"마크(로고)", 색은 "알 수 없음"도 가능, 캡슐 여부는 선택). 빠진 항목은 버튼 위에 "색·모양을 알려 주세요"처럼 안내한다.
2. **후보 비교와 선택**: 후보 최대 5개, 공식 값과 일치 항목, 의약품안전나라 링크, 출처 상자(제공 기관·자료 이름, "자료 기준 시점: 받은 시각", 마지막 갱신 성공/실패), 안내 "검색한 약의 후보입니다. / 확정된 결과가 아니니 복용 전 약사에게 확인해 주세요.", 맨 아래 "다른 알약 찾기"(입력값을 비우고 처음으로)
3. **약 정보와 질문**: 탭 요약 / 원문 / 질문하기. 원문(출처·수정일·받은 시각) / 요약(AI 작성 표시, 작성 모델 표시) / 질문 → (외부 전송 시) 가린 질문 확인("아래 문장으로 바뀌어 CLOVA·Claude(으)로 전송됩니다.") → 답변·근거 문단·규칙 검사·Claude 검토 결과. 처방약은 안내와 링크만. 하단에 "이 정보는 법적 효력이 없으며 의약품에 관한 모든 내용을 담고 있지 않습니다. / 복용 전 약사에게 확인하세요." 문구, 맨 아래 "다른 알약 찾기"
4. **화면 시안**: `pill-finder/` 정적 페이지(claude.ai/design 시안을 옮김, 예시 데이터로 동작). 디자인 수정 기록은 `pill-finder-handout.md`

## 8. 처리 한도 (앱 전체 기준, IP 저장 안 함)
- 사진: 한 번에 2장, 장당 5MB / 사진 읽기 하루 50회
- 후보: 최대 5개
- 질문: 300자, 하루 50회, 질문당 답변 작성 1회
- Claude 검토: 켰을 때 하루 최대 50회(질문 한도와 같음), 질문당 1회, 응답 길이 상한 `max_tokens` 4000 (API 직접 호출이라 `--max-budget-usd`는 쓰지 않음)
- CLOVA: 월 비용 상한(예: 5,000원), 넘으면 무료 모드로 전환
- 근거 문단: 최대 5개
- 요약: 약마다 1회 생성 후 재사용
- Local LLM: 동시 1건
- 자료 갱신: 한 번에 공공 API 최대 500회 호출

## 9. 실행 환경과 운영
- 서버: claude-code (2 vCPU·8GB, GPU 없음). 새 서버·유료 서비스·관리형 DB 없음.
- 앱: /opt/rag-lab-b를 새 폴더로 복사해 수정(FastAPI·정적 HTML). 원본은 그대로 둔다. 새 앱에서 LangSmith 전송은 끈다.
  - 2026-11-11 실제: 통째로 복사하지 않고 `/opt/pill-finder`에 약 기능만 새로 만들었다(`app.py`, `refresh.py`, `static/`, 포트 8000). 실습 경로는 처음부터 없다. 기존 코드(clova.py, Ollama·Chroma 연결)는 3·4단계에서 필요한 파일만 가져온다. 가상환경은 `/opt/rag-lab-b/.venv`를 같이 쓴다.
  - 2026-11-12: 8000번을 systemd 서비스 `pill-finder`로 상시 실행(재부팅·오류 시 자동 재시작). 하루 한도는 `data/limits.json`에 세어 다시 켜도 이어짐(같은 폴더를 쓰는 서버끼리 함께 셈). 서버 없이 보는 데모는 `plugin-lab/demo/`(실제 화면 + 녹화한 응답, GitHub Pages용)
  - 복사본에서는 실습용 경로와 파일(멘토 콘솔, 모델 비교, 답변 검토, 회사 문서 색인·원문 API `/api/docs/*`, 실습 자료 corpus·company_docs)을 **모두 지우고** 약 기능 경로만 남긴다. 기존 회사 문서 원문 API는 대외비도 돌려주고 접속 확인 기능이 없어, 누구나 쓰는 앱에 남기면 안 된다.
  - 복사할 때 원본의 `.env`는 가져오지 않는다. 새 앱의 키는 새로 설정한다.
- 로컬 실행 기록은 30일 뒤 자동 삭제한다.
- 새로 설치: Pillow(EXIF 제거·사진 축소). 나머지(FastAPI, chromadb, httpx, python-multipart)는 기존 가상환경에 있음.
- 키: CLOVA·Claude·공공데이터 키는 서버 환경변수로만 관리(기존 setup_env.py 방식). 브라우저 코드·기획서·로그·모델 입력에 넣지 않는다.
- 자료 갱신: **주 1회 자동 실행**(정해진 시각) + 같은 명령으로 지금 한 번 실행.
  - 언제: 매주 월요일 03:00, 서버 cron이 갱신 명령을 실행한다(확인 주기 주 1회).
  - 지금 한 번 실행: 같은 갱신 명령을 사람이 직접 실행한다.
  - 끄기: `AUTO_REFRESH=off`면 cron이 실행돼도 바로 종료한다. 완전히 끌 때는 cron 줄을 지운다.
  - 하는 일: ① 낱알 식별 자료 ② e약은요를 다시 받아 서버 파일을 교체하고,
    ③ 바뀐 약만 RAG 검색 자료(pill-docs)에서 다시 만들고, (2026-11-11 실제: 질문할 때 수정일을 비교해 그 약만 다시 색인하므로 갱신 명령은 색인하지 않음)
    ④ 내용이 바뀐 약의 저장된 쉬운 말 요약을 지운다(다음에 열 때 새로 생성).
  - 처리한 항목 기록: 약마다 품목일련번호와 변경일(`CHANGE_DATE`, `updateDe`)을 저장한다. 변경일이 같으면 다시 색인하지 않는다.
  - 새로 등록된 약은 후보 풀에 추가되고, 허가 취소·정보 변경도 함께 반영된다. 화면에 보이는 후보는 계속 최대 5개.
  - 한도: 한 번 실행에 공공 API 최대 500회. 동시에 두 번 실행되지 않게 잠금 파일을 쓴다.
  - 실패: 새 파일을 다 받은 뒤에만 교체하고, 실패하면 기존 파일을 유지한다. 다음 주 실행 때 다시 시도하며, 같은 항목은 최대 3번까지 다시 시도한 뒤 건너뛰고 기록한다.
  - 결과 알림: 메신저로 보내지 않는다. 서버 로컬 기록과 화면 출처 상자의 "마지막 갱신 시각·성공/실패"로만 표시한다.
  - 갱신은 CLOVA를 부르지 않는다(요약은 사용자가 약을 열 때 생성).

## 10. 진행 순서
1. 키 신청, 예시 응답으로 자료 구조 확정, 첫 주 시험(각인 인식률·가리기 정확도·요약 모델 비교·Local LLM 응답 시간)
2. 자료 받기·후보 비교 코드, 화면 1(직접 입력·이름 검색)·화면 2 — 무료 모드로 먼저 완성
3. e약은요 검색 자료, 화면 3(공식 정보·요약), Local LLM 요약·답변
4. 스위치 단계 추가(사진 읽기, CLOVA 요약·답변, 가리기, Claude 검토), 비용 카운터, 자동 갱신, 예외 상황, 완료 기준 점검

## 11. 완료 기준
1. 사진 읽기를 켠 상태에서 시험 약 10종 앞·뒤 사진을 올리면 8종 이상에서 정답이 후보 5개 안에 있다(값 수정 포함).
2. 첫 주 시험 결과(각인 정확 인식 수 / 10)를 기록하고 사진 기능 판단 기준에 따라 결정했다.
3. 일반의약품을 고르면 공식 원문과 쉬운 말 요약이 분리되어 보이고 출처·수정일·받은 시각이 보인다. 같은 약을 다시 열면 요약을 새로 만들지 않는다.
4. 처방약을 고르면 정보·질문 대신 안내와 링크만 보인다.
5. 외부 전송 단계를 켠 상태에서 개인정보가 섞인 연습 질문 10개 중 사용자 확인 전에 외부로 나간 질문이 0개이고, 8개 이상에서 해당 정보가 모두 가려진다.
6. 연습 질문 20개 모두 근거 문단이 함께 보이거나 "공식 자료에 없음"이 보인다.
7. Claude 검토를 켠 상태에서 근거 밖 문장을 넣은 답변 5개 중 4개 이상에 주의 표시가 붙는다.
   검토를 끈 상태에서는 Claude 호출이 0회이고 "검토하지 않은 답변"과 코드 규칙 검사 결과가 보인다.
8. CLOVA 키를 비우거나 공공 API를 끊었을 때 정해진 문구가 보이고, 화면·로그에 키나 요청 주소가 남지 않는다.
9. 실행 중 LangSmith 전송이 꺼져 있고 사진 파일이 서버에 남지 않는다.
10. 갱신 명령을 실행하면 받은 시각이 화면에 바뀌어 보이고, 갱신 전후 후보 풀의 약 개수를 기록한다.
11. 갱신을 연속 두 번 실행하면 두 번째에는 다시 색인한 약이 0개다. `AUTO_REFRESH=off`일 때 예약 실행이 아무것도 받지 않고 끝난다.
    공공 API를 끊고 실행하면 기존 자료가 그대로 남고 화면에 "마지막 갱신 실패"가 보인다.
12. 사진 없이 약 이름만 입력해도 일반의약품 정보 화면까지 갈 수 있고, 이 과정에서 외부 호출이 0회다(요약이 이미 저장된 경우).
13. **무료 모드**(`PHOTO_READ`·`CLOVA_TEXT`·`CLAUDE_REVIEW` 모두 끔)에서 각인·색·모양 입력 → 후보 → 정보 → 질문 답변까지 끝까지 동작하고, 공공 API 외 외부 호출이 0회이며, 질문 가리기 단계가 나타나지 않는다. Local LLM 답변 시간을 연습 질문 20개로 기록한다.
14. CLOVA 월 상한을 일부러 낮게 설정하면 상한을 넘은 뒤 해당 단계가 무료 모드로 바뀌고 화면에 표시된다.
15. 새 앱에서 약 기능 외 경로(예: `/console`, `/models`, `/review`, `/docs`, `/api/docs/source/...`)를 열면 모두 404다.
16. 사진을 올린 뒤 "사진으로 각인 읽기"를 누르기 전에는 CLOVA 호출이 0회이고, 자른 사진만 전송된다.
17. 검색 서버 또는 Local LLM 서버를 멈춘 상태에서 정해진 문구가 보이고, 가리기를 못 한 질문은 외부로 나가지 않는다.
18. "아이가 약을 여러 알 삼켰어요" 같은 연습 질문 5개 모두에서 119 안내가 답변보다 먼저 보인다.
19. 각인을 소문자·공백 포함·0과 O를 바꿔 입력해도 같은 후보가 나온다.
