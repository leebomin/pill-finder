### 만드는 방식
- **화면 그리기**: 상태(`s`)가 바뀌면 `render()`가 화면 전체를 다시 그림. 버튼은 `data-act` 이름으로 `ACT`의 함수를 부름.
- **글자 입력**: 입력칸은 다시 그리지 않고 `refresh()`로 버튼 상태·글자 수·검색 결과만 고침 → 한글 조합 입력이 끊기지 않음. 늦게 도착한 요약·원문은 그 탭을 보고 있을 때만 다시 그림.
- **보안**: 사용자가 쓴 글자와 서버에서 받은 약 이름·원문은 모두 `esc()`로 바꿔서 화면에 넣음. 키는 서버 `.env`에만 있고, 오류 문구·기록에 키나 요청 주소를 넣지 않음.
- **글꼴**: 디자인의 Inter·Cal Sans·나눔바른고딕 대신 서버에 있는 Pretendard 사용 → 화면이 외부 글꼴을 부르지 않음.
- **질문 진행 표시**: 질문은 POST로 보내고 응답을 SSE로 흘려받음(근거 찾기 → 답변 작성 → 규칙 검사 → Claude 검토). 기존 앱의 EventSource(GET)는 질문이 주소·기록에 남을 수 있어 쓰지 않음.

### 각인 비교 규칙 (`app.py`의 `norm`, `search`)
- 대소문자·공백·하이픈 무시, `0/O`, `1/I/l`, `5/S`, `8/B`는 같은 글자로 봄. 자료 각인 칸의 "마크"·"분할선" 글자(예: `V분할선T`)는 빼고 비교
- 완전 일치 40점 > 부분 일치 20점, 앞뒤를 바꿔서도 비교. 색 일치 +15, 모양 일치 +15, 캡슐 여부 일치 +10 → 상위 5개
- 부분 일치: 입력이 각인의 일부면 인정. 각인이 입력 안에 들어 있는 경우는 각인이 두 글자 이상일 때만(한 글자 각인 `Q`·`Z`가 아무 입력에나 걸려서)
- 각인을 입력하면 각인이 맞는 약만 후보(색·모양만 맞는 약은 수천 개)
- 한쪽 각인만 쓰면 빈 칸은 비교에서 빠짐. "각인 없음"은 앞·뒤 각인과 마크가 모두 없는 약, "마크(로고)"는 `MARK_CODE_*`나 각인 칸의 "마크" 표기로 거름
- 색은 "노랑, 투명"처럼 여러 개일 수 있어 앞·뒤 색 중 하나라도 맞으면 일치. 모양은 원형·타원형·장방형 외 8종을 "기타"로 묶음

### 자료 (공공데이터포털, 같은 키)
| 자료 | 건수 | 받는 방법 |
|---|---|---|
| 낱알식별 `MdcinGrnIdntfcInfoService03` (01·02는 폐기) | 25,501 | 한 번 최대 500행, 52회 호출 |
| e약은요 `DrbEasyDrugInfoService` | 4,749 | 500행씩 10회 호출 |

- 전체 갱신은 약 40초, 호출 62회(한 번 실행 한도 500회). 새 파일을 다 받은 뒤에만 교체하고, 실패하면 기존 자료를 그대로 두고 화면에 "마지막 갱신 실패"를 표시
- 낱알 자료의 일반의약품 5,635건 중 e약은요에 있는 약은 2,744건 → 나머지는 "공식 정보(e약은요)에 없는 약입니다" 안내와 의약품안전나라 링크
- 기획서와 달리 e약은요 본문에 HTML 태그는 없었음. 물약처럼 낱알 자료에 없는 일반의약품도 이름 검색으로 찾음

### 질문 처리 순서
1. 응급 표현("삼켰", "여러 알" 등)이 있으면 답을 기다리지 않고 119 안내를 먼저 표시
2. 외부 전송 단계(CLOVA·Claude)가 켜져 있으면: Qwen이 개인정보(이름·나이·병명·임신 등)를 [가림]으로 바꿈 → 사용자가 가린 문장을 확인해야 전송. 서버도 가리지 않은 질문은 거부
3. 근거 찾기: 질문한 약의 문단만 BGE-M3·Chroma(`pill-docs`)로 검색, 최대 5개. 전체를 미리 색인하면 몇 시간이 걸려 질문이 들어온 약만 그때 색인하고, e약은요 수정일이 바뀌면 다시 색인
4. 답변 작성: CLOVA(켬) 또는 Qwen3 4B(끔·CLOVA 실패·월 상한 초과). 근거로 답할 수 없으면 "공식 자료에 해당 내용이 없습니다"
5. 코드 규칙 검사: 단정 표현("드세요", "복용하시길" 등), 근거 번호 없는 문장, 없는 근거 번호
6. Claude 검토(켬): 가린 질문 + 근거 + 답변 + 약 이름만 Haiku 5.5로 보내 근거 밖 내용·단정적 복용 지시를 찾음. 실패하면 "검토를 마치지 못한 답변"
- 질문과 사진은 저장하지 않음. 하루 한도: 질문 50회, 사진 읽기 50회(앱 전체, 메모리)

### MCP 서버 (`pill_mcp.py`)
수업 예시 `company_docs_mcp.py`처럼 FastMCP로 만든 stdio 서버. 앱과 같은 함수·자료 파일·RAG를 그대로 씀(웹 화면과 같은 기능의 두 번째 입구).

| 도구 | 하는 일 |
|---|---|
| `search_pills` | 각인·색·모양·캡슐 → 후보 최대 5개와 일치 항목 |
| `find_drug_by_name` | 약 이름 → 최대 20개 (e약은요에만 있는 물약 포함) |
| `get_official_info` | 품목일련번호 → e약은요 공식 원문 항목별 |
| `find_evidence` | 품목일련번호 + 질문 → RAG 근거 문단 최대 5개 (답은 만들지 않음, 응급 표현이면 119 안내) |

- 모두 읽기 전용, CLOVA·Claude 호출 없음. 입력값 검사(각인 40자, 모양은 정해진 값만, 품목일련번호는 숫자만), 오류 문구는 앱 화면과 같음
- 등록: `claude mcp add pill-finder -s local -- /opt/rag-lab-b/.venv/bin/python /opt/pill-finder/pill_mcp.py` (이 프로젝트 폴더에서만, 확인 `claude mcp get pill-finder`, 지우기 `claude mcp remove pill-finder -s local`). 새 Claude Code 세션부터 도구가 보임

### 스위치 (`/opt/pill-finder/.env`, 지금은 모두 켬)
| 스위치 | 켰을 때 | 껐을 때(무료 모드) |
|---|---|---|
| `PHOTO_READ` | 사진 탭 보임. 자른 사진을 EXIF 제거·축소 후 HCX-005로 읽어 입력칸을 채움(한 장 약 2.3원) | 사진 탭 없음 |
| `CLOVA_TEXT` | 요약·답변을 CLOVA HCX-005가 작성 | Qwen3 4B가 작성 |
| `CLAUDE_REVIEW` | Claude Haiku 5.5가 답변 검토(API 키 사용) | "검토하지 않은 답변" + 코드 규칙 검사 |
| `CLOVA_MONTHLY_CAP_KRW` | 기본 5000원. 넘으면 그 달은 CLOVA 단계가 무료 모드로 바뀌고 첫 화면에 안내 | — |
| `AUTO_REFRESH` | 매주 월 03:00 예약 갱신 | `off`면 예약 실행만 건너뜀 |
- CLOVA 요약·답변은 기획서의 HCX-007·HCX-DASH-002 대신 HCX-005를 씀 → 두 모델 단가를 몰라 월 상한을 지킬 수 없어서
- CLOVA 사진은 `dataUri.data`에 `data:image/jpeg;base64,` 접두어가 있어야 함(없으면 40001 오류). 한 턴에 사진 1장만 돼서 앞·뒤를 서버에서 나란히 붙여 한 번만 호출

## 4. 실행 방법

```bash
cd /opt/pill-finder
/opt/rag-lab-b/.venv/bin/python refresh.py      # 자료 전체 받기 (처음 한 번, 이후는 cron)
/opt/rag-lab-b/.venv/bin/uvicorn app:app --host 0.0.0.0 --port 8000
```

- 브라우저: `http://<서버 공인 IP>:8000/` (공인 IP 확인: `curl ifconfig.me`)
- `10.0.1.x` 같은 내부 주소는 클라우드 안에서만 열림
- `https://`가 아니라 `http://`
- 안 열리면: 클라우드 보안 그룹의 8000번 허용 범위, 접속하는 네트워크(회사·학교망 차단) 확인
- 8000번은 systemd 서비스 `pill-finder`로 상시 실행(2026-11-12~, 서버 재부팅·오류 시 자동 재시작). `systemctl status|restart|stop pill-finder`, 기록은 `journalctl -u pill-finder`. `.env` 스위치를 바꾸면 `systemctl restart pill-finder`. 끄고 등록 해제: `systemctl disable --now pill-finder`
- 8001번(무료 모드)은 서비스가 아님 → 세션이 끝나면 꺼지므로 시연 때만 직접 실행
- 스위치를 잠깐 바꿔 보려면 실행할 때 환경변수를 앞에 붙임(`.env`보다 우선): `PHOTO_READ=off CLOVA_TEXT=off CLAUDE_REVIEW=off …uvicorn …` = 무료 모드
- 자동 갱신 확인: `crontab -l`. 완전히 끄려면 표시된 두 줄을 지움
- 자가 검사: `for f in test_search ai clova photo; do /opt/rag-lab-b/.venv/bin/python $f.py; done`

- 포트를 더 열기 어려우면: 8000번에서 `?free=1`로 무료 모드를 고르게 바꾸는 방법이 있음(끄기만 가능, 아직 안 만듦)

### 접속이 안 될 때 (2026-11-11 iPhone 점검 결과)
- 서버 쪽은 정상: 8000번 대기 중, 서버 방화벽(ufw) 꺼짐, 공인 IP로 접속하면 응답함
- 서버에서 10분 동안 들어오는 접속 시도를 지켜본 결과(`tcpdump`, 접속 시작 신호만 봄), iPhone 시도는 서버까지 오지 않은 것으로 판단 → 클라우드 보안 그룹(ACG)이 8000번을 특정 주소에서만 열어 둔 것으로 보임
- 화면 코드에는 iPhone Safari(iOS 13.4 이후)가 모르는 문법 없음
- 해결: 네이버 클라우드 콘솔 → Server → ACG → 인바운드에 `TCP / 접근 소스 / 포트 8000` 추가. 권한이 없으면 조교·강사에게 요청
- 모두(`0.0.0.0/0`)에게 열 때의 위험: 남이 하루 한도를 다 쓸 수 있음, CLOVA(수업 키)·Claude(본인 키) 비용, `http`라 폰과 서버 사이가 암호화되지 않음, 수업 서버 규칙 확인 필요 → 캡처만 필요하면 PC 브라우저의 기기 모드(F12 → Ctrl+Shift+M → iPhone 선택, `⋮` → Capture screenshot), 폰 시연이 필요하면 내 IP 하나(`/32`)만 잠깐 여는 것을 권함

## 6. 디자인 수정 기록

### 공통
- 직접 입력/사진/이름 검색, 요약/원문/질문하기 탭: 진한 연회색 둥근 네모로 감싸고 고른 칸은 흰색
- 세로 스크롤바가 생겨도 화면이 좌우로 흔들리지 않게 스크롤바 자리를 늘 비워 둠

### 화면 1 · 약 찾기
- 각인·색·모양을 모두 정해야 "후보 찾기"가 눌림 (색은 "알 수 없음", 각인은 "각인 없음"·"마크" 가능, 캡슐은 선택)
- 버튼 위에 빠진 항목 안내 (예: "색·모양을 알려 주세요")
- 각인 안내: "한쪽에만 있으면 다른 칸은 비워 두세요. 대소문자·띄어쓰기는 무시합니다."
- 사진 탭 버튼: "후보 찾기" → "사진으로 각인 읽기" + 아래 안내 "위치 정보를 지운 뒤 CLOVA로 보내 읽고, 사진은 저장하지 않습니다." (누르면 값을 읽어 입력칸에 채우고, 확인 후 "후보 찾기")

### 화면 2 · 후보 비교
- 안내: "검색한 약의 후보입니다. / 확정된 결과가 아니니 복용 전 약사에게 확인해 주세요."
- 검색 조건 줄과 각인 값 줄의 글씨체를 다른 글씨와 같게, 회사 이름과 각인 값 줄 사이를 넓힘
- 배지 색: 일반 = 연한 파랑, 각인 완전·색·모양·캡슐 일치 = 연한 초록, 각인 부분 일치 = 연한 노랑
- 출처 상자: "자료 기준 시점: (받은 시각)", "프로토타입 예시 데이터" 삭제
- 맨 아래 연한 초록 "다른 알약 찾기" 버튼 (입력값을 비우고 처음으로)

### 화면 3 · 약 정보와 질문
- 약 종류: 상자 없이 동그라미 + 글씨, 약 이름과 왼쪽 정렬 (일반 = 연한 파랑, 전문 = 연한 노랑)
- 탭 이름: 요약 / 원문 / 질문하기
- 요약 제목 앞 아이콘: 무슨 약인가요(알약) · 어떻게 복용하나요(시계) · 주의할 점(경고)
- 원문 제목: 효능, 사용법, 경고, 복용 전 주의사항, 함께 복용하면 안 되는 약, 부작용, 보관
- "AI 작성 · 모델 이름" 배지 = 연한 분홍 (요약·답변 모두)
- 글 본문은 왼쪽 정렬 + 줄 길이 고르게 나누기(`text-wrap: pretty`, 양쪽 정렬은 단어 사이가 벌어져 뺌), "머리·근육·생리통"처럼 ·로 이은 말은 줄 중간에서 끊지 않음
- 질문 입력 글씨 = 예시 질문과 같은 13px, "공식 자료에 있는 내용만 답합니다" 삭제
- 진행 문구: "개인정보를 가리는 중입니다" / 확인 문구: "아래 문장으로 바뀌어 CLOVA·Claude(으)로 전송됩니다."
- 맨 아래 안내: "이 정보는 법적 효력이 없으며 의약품에 관한 모든 내용을 담고 있지 않습니다. / 복용 전 약사에게 확인하세요." (12px, 가운데 정렬)
- 맨 아래 "다른 알약 찾기" 버튼

### 실제 앱에서 더한 화면 (시안에는 없음)
- 사진 칸: 점선 자르기 상자를 끌어 옮기고 오른쪽 아래 점으로 크기 조절(키보드: 화살표 이동, Shift+화살표 크기), 아래 안내 "점선 상자를 끌어 알약만 들어가게 맞춰 주세요. 상자 안만 보냅니다."
- 사진에서 읽은 값이 채워지면 "사진에서 읽은 값입니다. 알약과 비교해 틀린 곳을 고쳐 주세요."
- 요약: 처음 여는 약은 "쉬운 말 요약을 만드는 중입니다. 처음 여는 약은 1분쯤 걸릴 수 있습니다." / 요약에 원문에 없는 숫자가 있으면 "복용량·횟수는 원문 탭에서 확인해 주세요" 경고(Qwen이 "4,000"을 "4,00이나"로 쓰는 일이 있음)
- 질문: 단계 목록(대기 → 진행 중 → 완료/건너뜀/실패), 답변 아래 "본인 상황에 맞는지는 약사에게 확인해 주세요.", 규칙 검사 건수, Claude 검토 결과(완료 / 주의 + 확인이 필요한 부분 / 실패 / 꺼짐)
- e약은요에 없는 일반의약품: "공식 정보(e약은요)에 없는 약입니다"
- CLOVA 월 상한 도달: 첫 화면에 "이번 달 CLOVA 사용 한도에 도달해 사진 읽기 없이 직접 입력으로 찾고, 요약·답변은 Local LLM이 작성합니다."
- 의약품안전나라 링크: 해당 약의 상세 페이지로 바로 연결
