### 만드는 방식
- **화면 그리기**: 상태(`s`)가 바뀌면 `render()`가 화면 전체를 다시 그림. 버튼은 `data-act` 이름으로 `ACT`의 함수를 부름
- **글자 입력**: 입력칸은 다시 그리지 않고 `refresh()`로 버튼 상태·글자 수·검색 결과만 고침 → 한글 조합 입력이 끊기지 않음
- **보안**: 사용자 글자와 서버에서 받은 약 이름·원문은 모두 `esc()`로 바꿔 넣음. 키는 서버 `.env`에만 있고 오류 문구·기록에 키나 요청 주소를 넣지 않음
- **글꼴**: Pretendard를 앱에 넣어 외부 글꼴을 부르지 않음
- **질문 진행 표시**: 질문은 POST로 보내고 응답을 SSE로 흘려받음(EventSource(GET)는 질문이 주소·기록에 남을 수 있어 안 씀)
- **하루 한도**: `data/limits.json`에 파일 잠금으로 셈 → 서버를 다시 켜도 이어서 세고, 같은 폴더를 쓰는 서버(8000·8001)는 함께 셈

### 각인 비교 규칙 (`app.py`의 `norm`, `search`)
- 대소문자·공백·하이픈 무시, `0/O`, `1/I/l`, `5/S`, `8/B`는 같은 글자. 자료 각인 칸의 "마크"·"분할선" 글자는 빼고 비교
- 완전 일치 40점 > 부분 일치 20점, 앞뒤를 바꿔서도 비교. 색 +15, 모양 +15, 캡슐 여부 +10 → 상위 5개
- 부분 일치: 입력이 각인의 일부면 인정. 각인이 입력 안에 들어 있는 경우는 각인이 두 글자 이상일 때만
- 각인을 입력하면 각인이 맞는 약만 후보. 한쪽 각인만 쓰면 빈 칸은 비교에서 빠짐. "각인 없음"·"마크(로고)" 선택 가능
- 색은 여러 개일 수 있어 앞·뒤 색 중 하나라도 맞으면 일치. 모양은 원형·타원형·장방형 외 8종을 "기타"로 묶음

### 질문 처리 순서
1. **응급 표현**이 있으면 답을 기다리지 않고 119 안내를 먼저 표시(`static/app.js`, `pill_mcp.py`에 같은 식). 표현: 삼켰, 과다, 과량, 많이 먹, 여러 알, 한꺼번에, 다 먹었, 다 먹어버, 잘못 먹, 통째, "여러·몇·숫자 + 개·알·번·통·병 + 먹었·삼켰·복용했"
2. 외부 전송 단계(CLOVA·Claude)가 켜져 있으면 **가리기**: Qwen이 개인정보를 [가림]으로 바꾸고, 코드 규칙(`ai.py` `MASK_RULES`)이 놓친 것을 한 번 더 가림 → 사용자가 가린 문장을 확인해야 전송. 서버도 가리지 않은 질문은 거부. 코드 규칙: 나이(숫자+살·세·개월·대), 임신·임산부·임부·산모·수유, 전화번호·이메일, 학교(○○대학교·고등학교 등), 직장("○○ 다니는·근무"), 병명(고혈압·당뇨 등, "○○병", "○○염", "○○ 진단"의 앞말), 투석·항암·보균·이식, 시·도와 뒤의 시·구·군·동, "○○구에 사는". Qwen 출력이 여러 줄이면 첫 줄만 씀
3. **근거 찾기**: 질문한 약의 문단만 BGE-M3·Chroma(`pill-docs`)로 최대 5개. 질문이 들어온 약만 그때 색인, 수정일이 바뀌면 다시 색인
4. **답변 작성**: CLOVA(켬) 또는 Qwen3 4B(끔·CLOVA 실패·월 상한 초과). 근거로 답할 수 없으면 "공식 자료에 해당 내용이 없습니다"
5. **코드 규칙 검사**: 단정 표현, 근거 번호 없는 문장, 없는 근거 번호
6. **Claude 검토**(켬): 가린 질문 + 근거 + 답변 + 약 이름만 Haiku 5.5로 보냄. 실패하면 "검토를 마치지 못한 답변"
- 질문과 사진은 저장하지 않음. 하루 한도: 질문 50회, 사진 읽기 50회(앱 전체)

### MCP 서버 (`pill_mcp.py`)
FastMCP stdio 서버. 앱과 같은 함수·자료 파일·RAG를 씀(웹 화면과 같은 기능의 두 번째 입구).

| 도구 | 하는 일 |
|---|---|
| `search_pills` | 각인·색·모양·캡슐 → 후보 최대 5개와 일치 항목 |
| `find_drug_by_name` | 약 이름 → 최대 20개 (e약은요에만 있는 물약 포함) |
| `get_official_info` | 품목일련번호 → e약은요 공식 원문 항목별 |
| `find_evidence` | 품목일련번호 + 질문 → RAG 근거 문단 최대 5개 (답은 만들지 않음, 응급 표현이면 119 안내) |

- 모두 읽기 전용, CLOVA·Claude 호출 없음, 입력값 검사
- 등록: `claude mcp add pill-finder -s local -- /opt/rag-lab-b/.venv/bin/python /opt/pill-finder/pill_mcp.py` (확인 `claude mcp get pill-finder`, 지우기 `claude mcp remove pill-finder -s local`)
- 과제 원문 기준: 앱이 순서를 정하는 단계는 HTTP, Claude가 도구를 고르는 단계만 MCP → 앱 안에서는 MCP가 필요 없음. `pill_mcp.py`는 "새 자료를 찾는 검색 MCP 도구를 새로 만든다"에 해당하는 추가 작업

## 4. 실행 방법

- **8000번(스위치 켬)**: systemd 서비스 `pill-finder`로 늘 실행. 재부팅·오류 시 자동으로 다시 켜짐
  - 상태 `systemctl status pill-finder`, 다시 시작 `systemctl restart pill-finder`(`.env`를 바꾼 뒤), 기록 `journalctl -u pill-finder`, 끄고 등록 해제 `systemctl disable --now pill-finder`
- **8001번(무료 모드)**: 필요할 때만 직접 실행 → `cd /opt/pill-finder && PHOTO_READ=off CLOVA_TEXT=off CLAUDE_REVIEW=off /opt/rag-lab-b/.venv/bin/uvicorn app:app --host 0.0.0.0 --port 8001`
- 자료 다시 받기: `/opt/rag-lab-b/.venv/bin/python refresh.py` (자동 갱신 확인 `crontab -l`, 완전히 끄려면 표시된 두 줄 삭제)
- 자가 검사: `for f in test_search ai clova photo; do /opt/rag-lab-b/.venv/bin/python $f.py; done`
- 브라우저: `http://<서버 공인 IP>:8000/` (`curl ifconfig.me`로 공인 IP 확인, `https` 아님, `10.0.1.x`는 내부 주소라 안 열림)

### 밖에서 안 열릴 때 (2026-11-11 iPhone 점검)
- 서버는 정상(8000번 대기, ufw 꺼짐, 공인 IP로 응답). 10분간 `tcpdump`로 본 결과 iPhone 접속 시도가 서버까지 오지 않음 → 클라우드 보안 그룹(ACG)이 막는 것으로 판단
- 해결: 네이버 클라우드 콘솔 → Server → ACG → 인바운드에 `TCP / 접근 소스 / 8000` 추가(권한이 없으면 조교·강사에게 요청)
- 모두(`0.0.0.0/0`)에게 열 때의 위험: 남이 하루 한도를 다 씀, CLOVA(수업 키)·Claude(본인 키) 비용, `http`라 암호화 안 됨 → 폰 시연은 내 IP 하나(`/32`)만 잠깐 열기를 권함. **누구나 보게 하려면 데모 사이트(5장)를 쓰면 포트를 열 필요가 없음**

## 8. 디자인 수정 기록

### 공통
- 탭 묶음(직접 입력/사진/이름 검색, 요약/원문/질문하기): 진한 연회색 둥근 네모, 고른 칸은 흰색
- 스크롤바 자리를 늘 비워 화면이 좌우로 흔들리지 않게 함

### 화면 1 · 약 찾기
- 각인·색·모양을 모두 정해야 "후보 찾기"가 눌림(색 "알 수 없음", 각인 "각인 없음"·"마크" 가능, 캡슐은 선택), 버튼 위에 빠진 항목 안내
- 각인 안내 "한쪽에만 있으면 다른 칸은 비워 두세요. 대소문자·띄어쓰기는 무시합니다."
- 사진 탭 버튼 "사진으로 각인 읽기" + "위치 정보를 지운 뒤 CLOVA로 보내 읽고, 사진은 저장하지 않습니다."

### 화면 2 · 후보 비교
- 안내 "검색한 약의 후보입니다. / 확정된 결과가 아니니 복용 전 약사에게 확인해 주세요."
- 배지 색: 일반 = 연한 파랑, 각인 완전·색·모양·캡슐 일치 = 연한 초록, 각인 부분 일치 = 연한 노랑
- 출처 상자 "자료 기준 시점: (받은 시각)", 맨 아래 연한 초록 "다른 알약 찾기"

### 화면 3 · 약 정보와 질문
- 약 종류는 동그라미 + 글씨(일반 = 연한 파랑, 전문 = 연한 노랑), 탭 이름 요약 / 원문 / 질문하기
- 요약 제목 아이콘: 무슨 약인가요(알약) · 어떻게 복용하나요(시계) · 주의할 점(경고), 원문 제목 7개
- "AI 작성 · 모델 이름" 배지 = 연한 분홍, 본문 왼쪽 정렬 + `text-wrap: pretty`, ·로 이은 말은 줄 중간에서 안 끊음
- 진행 문구 "개인정보를 가리는 중입니다", 확인 문구 "아래 문장으로 바뀌어 CLOVA·Claude(으)로 전송됩니다."
- 맨 아래 "이 정보는 법적 효력이 없으며 … / 복용 전 약사에게 확인하세요." + "다른 알약 찾기"

### 실제 앱에서 더한 화면 (시안에는 없음)
- 사진 자르기 상자(끌기·크기 조절·키보드), 사진에서 읽은 값 안내
- 요약 만드는 중 안내, 원문에 없는 숫자 경고
- 질문 단계 목록(대기 → 진행 중 → 완료/건너뜀/실패), 규칙 검사 건수, Claude 검토 결과
- e약은요에 없는 약 안내, CLOVA 월 상한 안내, 의약품안전나라 상세 링크
